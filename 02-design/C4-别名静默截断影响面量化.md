### 2.4 理论阈值与敏感性（实测合成，非推测）

`FTS_QUERY_MAX_CJK_RUNS=2` ⇒ 只取最长两段中文连续段；长度 `L≥3` 的段产出 `L−2` 个窗口，`L=2` 产出 1 个。因此：

- **单段**达 24 窗口需 `L ≥ 26`（`L−2 ≥ 24`）。合成验证：`L=24→W=22`、`L=25→W=23`、`L=26→W=24 (hit_cap=True)`、`L=27→W=25`。
- **两段**均 `≥3` 时需 `L1+L2 ≥ 28`（`W = L1+L2−4`）。
- `query[:400]` 上限不足以拦住它（400 字显然可远超 26），所以缺陷是**可由长问句触发的真实缺陷**，只是评测集里没有这么长的中文连续段。样本最大 `top-2 合计中文字符 = 27`，但被标点拆成两段，`W` 因此只有 23 —— **离触发仅差 1 个窗口**。

### 2.5 「占比是否非 0」的明确结论

- **可测样本（实测）**：**占比 = 0，非 0 不成立**。核心 206 条 0 命中，全源并集 233 条 0 命中，三份生产 eval 日志 0 命中。
- **精确 217 条**：**未实测**。11 条题面不可得（真库不可达），不能宣称「217 条里 0 条」。基于「这 11 条 = +1 可答 / +10 不可答、且现有 206 条里最长也只差 1 个窗口」做**推断**：217 条大概率同为 0，但**这是推断，不是结论**。若需把 U-C 彻底关掉，必须按 §2.2 的「真库可达时」脚本跑一次（成本低，纯函数，不需起服务、不需 LLM）。

### 2.6 更宽的失效模式：部分截断（U-C 原口径没覆盖）★

`:145` 的实际语义是「**合并后重截到 24**」，不只是「已达 24 才全吞」。设 `A_cjk(q)` 为该 query 经 `alias_index_tokens(alias_map)` 得到的**新增 CJK 索引词元数**（取决于真库 `kb_terms` 命中情况）：

```
被丢弃的别名数 = max(0, W_post + A_cjk − 24)
```

- `W_pre ≥ 24` ⇒ **全部别名被吞**（U-C 口径）。
- `W_pre < 24` 但 `W_pre + A_cjk > 24` ⇒ **部分别名被吞**（U-C 口径漏掉的更宽面）。

`alias_index_tokens`（`lexicon.py:109-119`）对每个别名做 `to_fts_text(alias).split()`：一个 4 字中文别名展开成 **3 个 2-gram**（设计文档 F5）。`load_alias_map` 最多 `ILIKE_MAX_TERMS=3` 个键 × `LEXICON_MAX_ALIASES_PER_KEY=2` = 6 个顶层写法，故 `A_cjk` 在常规情形下可达个位数甚至十几。**只要某条 query 剩余容量小于它的别名词元数，就会被截断。**

实测剩余容量分布（并集 233 条，纯函数可复算）：

| 剩余别名容量 `24−W` | query 数 | 占比 | 含义 |
|---|---|---|---|
| ≤ 1 | **2** | 0.86% | 只要别名 ≥2 个词元就开始丢 |
| ≤ 2 | 2 | 0.86% | — |
| ≤ 3 | 3 | 1.29% | — |
| ≤ 4 | 4 | 1.72% | — |
| ≤ 6 | **7** | 3.00% | 常规 6 个顶层写法的量级 |
| ≤ 8 | 12 | 5.15% | — |
| ≤ 12 | 62 | 26.61% | — |

**这一层无法量化到底有多少条真的丢了别名**，因为 `alias_map` 来自不可达真库的 `kb_terms` 表。诚实结论：**「全吞」占比实测 0；「部分吞」的触发条件在 2~7 条 query 上成立，但实际发生数 = 未知区**（§6-U1）。这直接推翻一个容易下的错判——「0% ⇒ 修它零行为改动、零基线风险」。**修法会改变这批用例的 tsquery 输出**（§3.3）。

### 2.7 缓解事实（降低真实业务影响，非修复）

1. **ILIKE 路不受影响**：`build_ilike_pattern(ilike_terms, alias_map)`（`:271`）无截断，别名作为并列 OR 分支始终存在（F4）。因此 F6 只让 **FTS 一路**丢失别名扩展，不是「查询扩展整体失效」；两路结果在 RRF 里互补。
2. **图链接调用不受影响**：`graph/linking.py:237` 单实参调用，`alias_tokens` 为空 ⇒ `:142 if` 分支根本不执行。
3. **关闭词表扩展时不受影响**：`ALIAS_EXPANSION_ENABLED=False` 或 `alias_map={}` ⇒ `alias_index_tokens({}) == []` ⇒ `if alias_tokens` 为假。

## 3. 修复方案评估

### 3.1 独立预算形态的修法（对齐增量设计 §2.2.4 的 keyword-only 默认参）

**核心契约**（与 §2.2.4 逐字同型）：**原 query 窗口集合冻结**——`:128` 的 `[:24]` 一行不动；别名走**独立预算**作为附加 OR 项注入，**不再把合并后的 `windows` 重截回 24**；`extra_*` 为空时返回值与改动前**逐字节相同**。

```python
# ① code/apps/api/app/config/decisions.py —— 新增 1 个冻结常量（影响检索口径，故放 decisions，符合 §9.5 判据）
LEXICON_FTS_ALIAS_MAX_TERMS: Final[int] = 6
"""词表别名在 tsquery 上的独立词元预算，不占 FTS_QUERY_MAX_TERMS 名额。
与 WIKI_NAV_MAX_FTS_TOKENS=6 同量级：ILIKE_MAX_TERMS=3 × LEXICON_MAX_ALIASES_PER_KEY=2 = 6 个顶层写法。"""

# ② code/apps/api/app/services/keyword_text.py
def build_fts_query(
    query: str,
    alias_tokens: list[str] | None = None,
    *,
    alias_max_terms: int = decisions.LEXICON_FTS_ALIAS_MAX_TERMS,   # keyword-only 默认参
) -> str | None:
    ...
    windows = _dedupe(windows)[: decisions.FTS_QUERY_MAX_TERMS]      # :128 原样，不动
    ascii_items = _dedupe(...)[: decisions.FTS_QUERY_MAX_TERMS]      # :138 原样，不动
    if alias_tokens:
        extra = list(dict.fromkeys(alias_tokens))[:alias_max_terms]   # 别名侧独立扁平预算
        cjk_aliases   = [t for t in extra if _CJK_RE.fullmatch(t)]
        ascii_aliases = [t for t in extra if not _CJK_RE.fullmatch(t)]
        windows     = _dedupe(windows + cjk_aliases)                  # 不再重截回 24
        ascii_items = _dedupe(ascii_items + ascii_aliases)            # 不再重截回 24
```

要点与边界（不展开导航接线细节，聚焦 C4）：

- **只加 keyword-only 默认参**，所有既有调用点**一个实参都不用改**（§2.2.4 契约）。`build_ilike_pattern` **完全不改**。
- 别名侧仍需一个有名字、有常量、可调的预算：否则 6 个中文别名各展开 ≤11 个 2-gram 会把 tsquery 撑到 24+66。**独立预算 ≠ 无预算**。
- **「不报错、不打点」也要修**：把「静默」改成可见。为保持 `keyword_text.py` 纯函数（当前无 `logging`、无 IO），建议在 `retrieve/__init__.py:285` 调用侧对 `alias_index_tokens(alias_map)` 的长度与 `alias_max_terms` 比较，`metrics.incr("rag.lexicon.fts_alias_dropped", n)`；或先只打点、不改预算（见 §3.5「打点先行」）。
- **必须补 2 条针对性单测**（现有测试的两半没交叉，§1.4）：
  1. `build_fts_query("".join(chr(0x4E00+i) for i in range(26)), ["访问"])` ⇒ `W=24`，断言输出**含** `访问`（当前实现不含）。
  2. ASCII 同型：`build_fts_query(" ".join(f"token{i}" for i in range(40)), ["accesstoken"])` ⇒ 断言 ASCII 组含 `accesstoken`。
  3. 断言 `alias_tokens=[]` / `None` 时，对 217 条 + 20 条代表问句输出与 **Golden 快照逐字节相同**。

### 3.4 对 `config_fingerprint` 的影响

**结论：完全不变（实测读源码可复算）。**

- `config_fingerprint(snapshot)`（`config_profile.py:143-153`）= `sha1(json.dumps({k: snap.get(k) for k in CROSS_ROLE_FIELDS if k in snap}, sort_keys=True))[:12]`。

- 因此：新增 `LEXICON_FTS_ALIAS_MAX_TERMS`、修改 `build_fts_query` 函数体 ⇒ **`config_fingerprint` 不变**，api / worker 启动横幅的指纹比对不会误报、也不会漏报（本来就不该由它表达代码契约）。

### 3.6 明确建议：**随第 4 步一起修**

> **交付时区分决策归属**：以下是**我的专业建议**，不是已确认决策。C4 / U-C 的处置措辞写在 `02-design/第4步-wiki导航增量设计.md` 里，**须由管家节点（team-lead）裁决**；按任务约束我未改动该文件。

**理由（4 条）**

1. **U-C 的原始判据实测 0%**（0/206 核心、0/233 并集），「若非 0，单开一项修」的条件**不触发** —— 没有「立刻、单独、马上修」的紧迫性。
2. **但也不该「不修」**：缺陷已被合成反例证明确凿存在（§1.5），且**仍然静默**（既不报错也不打点）；§2.6 显示 2~7 条 query 已具备「部分截断」触发条件；长问句（单段 ≥26 汉字）在真实用户流量里完全可能出现，评测集覆盖不到不等于线上不会发生（与主文档 §14.6「没测到 ≠ 没影响」同型）。
3. **独立预算修法不是零行为改动**，仍要付一次全量 217 复跑（78 分钟 + 完整栈 + 真库）。第 4 步本来就付这一次 ⇒ **合并摊薄**；单开一项修 = 现在付一次、第 4 步再付一次。

import sys, types, importlib.util, json, re, os, ast

B = "code/apps/api/app"
def load(n, p):
    s = importlib.util.spec_from_file_location(n, p)
    m = importlib.util.module_from_spec(s); sys.modules[n] = m
    s.loader.exec_module(m); return m

def stats(q):
    """逐行复刻 build_fts_query :110-138（全部用模块自身的私有函数）"""
    t = kw._normalize(q[:400])
    runs = sorted(kw._CJK_RE.findall(t), key=len, reverse=True)[:d.FTS_QUERY_MAX_CJK_RUNS]
    if any(len(r) > 1 for r in runs): runs = [r for r in runs if len(r) > 1]
    ws = []
    for run in runs:
        g = kw._bigrams(run)
        if len(g) == 1: ws.append(g[0])
        else: ws.extend(f"({g[i]} & {g[i+1]})" for i in range(len(g) - 1))
    w = len(kw._dedupe(ws))
    a = len(kw._dedupe(
        kw._ASCII_RE.findall(t)
        + [f"({l} & {x})" for l, x in kw._model_codes(t) if len(l) >= 2]
    ))
    return dict(w=w, w_post=min(w, CAP), a=a, a_post=min(a, CAP),
                hit_cap=w >= CAP, a_hit=a >= CAP,
                cjk=sum(len(r) for r in runs), q=q)

def verify(s):
    """与真实 build_fts_query 输出交叉校验：| 数 == 两组内部分隔符之和"""
    tsq = kw.build_fts_query(s["q"])
    if tsq is None: return s["w_post"] == 0 and s["a_post"] == 0
    exp = (s["w_post"] - 1 if s["w_post"] else 0) + (s["a_post"] - 1 if s["a_post"] else 0)
    return tsq.count(" | ") == exp

src["seed_eval.py"] = [

    if isinstance(n, ast.Assign) and isinstance(n.value, (ast.List, ast.Tuple))

    if isinstance(e, ast.Constant) and isinstance(e.value, str)
    and ("？" in e.value or "?" in e.value)
]
src["diag_cases.json"] = [c["q"] for c in json.load(open(".workbuddy/diag_cases.json", encoding="utf-8"))]

for k, v in src.items():

    print(f"{k:32s} n={len(uniq):4d} cap_hit={sum(s['hit_cap'] for s in st):3d} "
          f"a_hit={sum(s['a_hit'] for s in st):3d} maxW={max(s['w'] for s in st):3d} "
          f"maxCJK={max(s['cjk'] for s in st):3d} verify={all(verify(s) for s in st)}")

union = list(dict.fromkeys(q for v in src.values() for q in v))
st = [stats(q) for q in union]
print("\nUNION n =", len(union), "cap_hit =", sum(s["hit_cap"] for s in st),
      "a_hit =", sum(s["a_hit"] for s in st),
      "maxW =", max(s["w"] for s in st), "verify =", all(verify(s) for s in st))

    for item in base.strip("()").split(" | "):
        assert item in extended, f"原 ASCII 词元 {item} 被挤掉"
