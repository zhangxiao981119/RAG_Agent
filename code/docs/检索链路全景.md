> **文档目的**：把 `code/apps/api/app/services/retrieve/` 主链路，连同图召回（GraphRAG）、wiki 导航（Wiki Navigation）、权限下推（ACL Pushdown）等旁路，按「请求进来 → 召回 → 融合 → 补全 → 重排 → 阈值 → 拒答 → 旁路」主线钉死。所有常量均标注 `文件:行号`，可回源码复算。

## 0. 一图流（请求生命周期）

1. **API 层取权限**：从 `CurrentUser` 取权限，**不信任前端**，展开 `pushdown_params` → 传入 `retrieve()`。
2. **主链路**（`retrieve()` 内）：查询归一 → [wiki 导航（默认关）] → 三路混合召回（向量 / FTS tsquery / ILIKE 子串），每路带权限四闸门 → RRF（RRF，Reciprocal Rank Fusion，倒数排名融合，k=60）融合 → 取候选 50 → [图召回（默认关）] → [章节 / 表格补全] → 重排（Rerank，默认关）→ 阈值 0.50 闸门 → 拒答判定 → 生成层（注入检测 / 三级记忆 / 引用双向校验）。
3. **全程埋点**：`path_stats` 记录各路 covered / unique，按 v1.2 契约写图路 `graph_covered` / `graph_unique`。

## 2. 查询归一与扩词

| 步骤 | 函数 / 常量 | 调用点 | 作用 |
|---|---|---|---|
| 归一 | `normalize_query_text(query[:400])` | `:302`（wiki 命中时） | 截断到 400 字符并清洗 |
| ILIKE 词元 | `build_ilike_terms(query)` | `:248` | 按疑问 / 功能词切段，按长度降序取 `ILIKE_MAX_TERMS=3` 个 |

| FTS 查询串 | `build_fts_query(query, alias_index_tokens(alias_map), extra_index_tokens=wiki_fts_tokens)` | `:352-357`（受 `KEYWORD_TSQUERY_ENABLED=True` 控，`:358`） | 3 字窗口 OR，独立预算 |

要点：

- FTS（FTS，Full-Text Search，全文检索）走「中文 2-gram（二元组）→ 3 字窗口 OR（OR，逻辑或）」，预算 `FTS_QUERY_MAX_TERMS=24`，中文连续段上限 `FTS_QUERY_MAX_CJK_RUNS=2`。
- 别名独立预算 `LEXICON_FTS_ALIAS_MAX_TERMS=6`（`ILIKE_MAX_TERMS(3) × LEXICON_MAX_ALIASES_PER_KEY(2) = 6`），**不再被主词元截断吞掉**（修复 C4 / F6 别名静默截断）。
- wiki 导航词元以**独立预算** `extra_terms` / `extra_index_tokens` 注入，关闭态逐字节等价。

## 3. 三路混合召回 + 权限四闸门

三路**分别独立** `session.execute`，**未 UNION**（`:227` / `:323` / `:364`）。每路同带 `_WHERE_BASE` 权限四闸门。

### 3.1 召回预算

三路每路 `LIMIT :limit = TOP_K_RECALL = 50`（`decisions.py:167`）。候选去重后 `candidate_ids = sorted_ids[:50]`（`:405`）。重排取用 `TOP_K_RERANK = 8`（`decisions.py:168`）。

### 3.2 三路 SQL

- **向量** `_VECTOR_SQL_TEMPLATE:62-74`：余弦 `1 - (c.embedding <=> :q)`（`<=> ` 是 PostgreSQL 向量余弦距离算子），过滤 `embedding_model` / `embedding_text_version`，按 `<=>` 升序 LIMIT。
- **FTS tsquery（tsquery，PostgreSQL 全文检索查询语法）** `_KEYWORD_FTS_SQL:114-124`：`c.fts_vec @@ to_tsquery('simple', :tsquery)`，`ts_rank(...)` 打分；`fts_vec` 是生成列，走 `idx_chunk_fts_vec` GIN 索引（GIN，Generalized Inverted Index，广义倒排索引）。
- **ILIKE 子串（ILIKE，PostgreSQL 大小写不敏感模糊匹配）** `_KEYWORD_SQL:87-101`：`c.content ~* :pattern OR c.heading_path ~* :pattern`（`~*` 是正则、大小写不敏感），按 `strpos` 命中位置排序。

### 3.3 权限四闸门（`_WHERE_BASE:48-53`）

```sql
WHERE c.tenant_id = :tenant_id
  AND c.is_latest = true
  AND c.level_rank <= :clearance            -- G1 密级
  AND c.kb_id = ANY(:authorized_kb_ids)     -- G2 知识库
  AND NOT (c.deny_subjects && :user_subjects)  -- G3 拒绝主体
  AND c.acl_tags && :user_subjects          -- G4 标签
```

- 绑定值 `retrieve` 内手动构造 `pushdown` 字典（`:208-213`）：`tenant_id / clearance / authorized_kb_ids / user_subjects`。
- 该 SQL 串与 `acl/visibility.py:27-33` 的 `PUSHDOWN_WHERE_SQL` **逐字相同**，被图召回、wiki 导航晚导入复用（同一字符串对象，存在漂移风险，需注意）。
- `chunks` 表无 `deleted_at`，用 `is_latest` 代替（`:45-47`）。

## 4. RRF 融合（Reciprocal Rank Fusion，倒数排名融合）

`_build_rrf_scores:172-184`：

```python
def _build_rrf_scores(*rank_lists) -> dict[uuid.UUID, float]:
    scores = {}
    for ranks in rank_lists:
        for rank, cid in enumerate(ranks):
            scores[cid] = scores.get(cid, 0.0) + 1.0 / (decisions.RRF_K + rank + 1)
    return scores
```

- **k 常量**：`RRF_K = 60`（`decisions.py:169`）。
- 调用 `:402`：`_build_rrf_scores(vector_ranks, fts_ranks, keyword_ranks)`（`rank_lists` 可任意扩展，便于后续加第四路）。
- 输出 `dict[chunk_id, float]`，`sorted_ids = sorted(..., key=rrf_scores, reverse=True)`（`:404`），前 50 为 `candidate_ids`（`:405`）。

## 5. 旁路补充（不进主排序 / 阈值）

| 旁路 | 位置 | 上限 | 预算（token） | 默认 |
|---|---|---|---|---|
| 章节补全（Section Recall） | L1 后、主排序前 | `SECTION_RECALL_MAX_CHUNKS=3` | `SECTION_RECALL_TOKEN_BUDGET=1200` | 开 |
| 表格回捞（Table Recall） | 同 | `TABLE_RECALL_MAX_CHUNKS=3` | `TABLE_RECALL_TOKEN_BUDGET=2048` | 开 |
| 图召回（Graph Recall） | L1 后、章节前 | `GRAPH_RECALL_MAX_CHUNKS=3` | `GRAPH_RECALL_TOKEN_BUDGET=1200` | **关** |
| wiki 导航（Wiki Nav） | 第 4 步、关键词召回前 | `WIKI_NAV_MAX_PAGES=1` | `WIKI_NAV_MAX_FTS_TOKENS=6` | **关** |

机制（章节补全为例 `:685-750`）：按命中片分数降序逐节分配预算 `budget_left = SECTION_RECALL_TOKEN_BUDGET`，`picked < max` 且 `row_tokens <= budget_left` 才补入，预算耗尽即停；产物 `section_chunks` 单独存放（`:811`），**不进 `retrieved` 排序与阈值**。

图召回片分数恒 0、wiki 导航仅作扩词，均**不污染阈值语义**。

### 9.2 statement_timeout 事务级三段式还原

`recall.py` 内：

- ① 保存原值 `previous_timeout = await _read_statement_timeout(session)`（`:286`）→ 读 `current_setting('statement_timeout')`，缺省回退 `"0"`（`:93-97`）。
- ② 设超时 `set_config('statement_timeout', :ms, true)`（`:287-290`），`true` = 事务级作用域（set_config 第三个参数为 true 时仅当前事务生效）。
- ③ 成功还原为**原值** `set_config('statement_timeout', :prev, true)`（`:309`，`:117-120`），**非硬编码 `'0'`**。
- rollback 路径（`:295,303`）只 `session.rollback()`（`:81`），事务随终了，不再发还原 SQL —— 避免「硬编码 0 还原」在失败路径上把上游超时设回 0 的隐患。

## 11. path_stats 埋点（v1.2 契约口径）

写入区 `retrieve/__init__.py:765-802`。

- 三路（vector / tsquery / ilike）`covered` / `unique`（`:771-778`）：

```python
path_stats[f"{name}_covered"] = len(covered)         # covered = final_ids & ids
```

- **图路 v1.2**（仅 `graph_enabled` 时写，`:792-795`）：

